## One window, one policy

Open a folder, type `bridle`, and a window opens: a chat with a local model, a code editor with diffs, project search, a real
terminal, and image input. The model reads and edits your project with tools. What each call may do is decided by a policy written
**in code, not in a prompt**.

<CardGrid>
  <Card title="Decides every call" icon="approve-check">
    Each tool call is classified and given a verdict before it runs. `ask` is never allowed, and a failure to decide blocks the call.
  </Card>
  <Card title="Keeps secrets out" icon="padlock">
    Secret files cannot be read. Secret-looking environment variables are blanked for shell tools. Secret values in output are redacted before the model sees them.
  </Card>
  <Card title="Runs on your GPU" icon="desktop">
    Models run through llama.cpp on your own machine, one GPU model at a time, guarded against running out of video memory. No cloud service is needed.
  </Card>
  <Card title="Catches loops" icon="warning">
    Repeated edits and repeated commands are refused, with the rule named, and the agent is told what to try next.
  </Card>
</CardGrid>

## What happens to a tool call

The window, the terminal UI and [OpenCode](https://opencode.ai) are different front ends to one decision path. Nothing a host does can skip it.

<div class="flow" role="img" aria-label="The model sends a tool call to the host. The policy and loop rules decide. An allowed call runs and its output is redacted before the model reads it. A refused call returns its reason to the model.">
  <div class="flow__node">Model<small>llama.cpp, on this machine</small></div>
  <div class="flow__arrow" aria-hidden="true">tool call</div>
  <div class="flow__node">Host<small>window, TUI or OpenCode</small></div>
  <div class="flow__arrow" aria-hidden="true">before it runs</div>
  <div class="flow__node flow__node--decide">Policy and loop rules<small>allow · ask · deny</small></div>
  <div class="flow__branches">
    <div class="flow__branch flow__branch--ok"><b>allow</b> The tool runs, secret values are redacted, the result goes back to the model.</div>
    <div class="flow__branch flow__branch--no"><b>ask or deny</b> The call is blocked and the reason goes back to the model.</div>
  </div>
</div>

Five calls, run through the real hook on Windows 11 against the example repository:

```text
read calc.py                      allow   READ_ONLY  tool_kind
read .env                         block   READ_ONLY  secret_file    ".env may contain credentials and is never sent to a model"
bash: cat .env                    block   READ_ONLY  secret_file    "shell access to it is denied"
bash: git status --short          allow   READ_ONLY  command_risk
bash: curl https://example.com    block   NETWORK    command_risk   "curl contacts the network"
```

## Beyond a single agent

<CardGrid>
  <Card title="A team and a board" icon="open-book">
    Named members (project manager, product owner, engineers, QA and more) sit on the right edge of the window. Tag one with `@`, and the work goes onto a board of issues the members split and work. [Team and board](./guides/team-and-board/)
  </Card>
  <Card title="Lanes for parallel work" icon="random">
    Give each member a separate working copy, review each one's diff, and merge them yourself. Nothing is written if two lanes conflict. [Lanes](./guides/lanes/)
  </Card>
  <Card title="A small-model fleet" icon="rocket">
    Small models loaded together while the big one is unloaded, with a scheduler that swaps them safely and a record that survives a crash. [The fleet](./guides/fleet/)
  </Card>
  <Card title="Web research and a browser" icon="external">
    Search, read pages, download files with a checksum, and drive a pinned Chromium. Off by default, and behind Bridle's own proxy. [Web research](./guides/web-research/)
  </Card>
</CardGrid>

## Start in five minutes

<Tabs>
  <TabItem label="From the release zip">
    <Steps>
    1. Unpack `bridle-<version>-windows-x64.zip` and run `install.cmd`.
    2. Open a new terminal in a project folder and run `bridle`.
    3. The first time, Bridle asks where your models and the llama.cpp runtime are, and offers to set up the folder.
    </Steps>
  </TabItem>
  <TabItem label="From source">
    ```bat
    git clone https://github.com/kushagrathisside/bridle.git
    cd bridle
    scripts\dev.cmd release
    scripts\dev.cmd install
    ```
  </TabItem>
</Tabs>

Model weights are **not** included. The [models guide](./guides/serve-models/) lists the files and their SHA-256 values.

<Aside type="caution" title="What Bridle is not">
Bridle is not a sandbox: an allowed test run executes code the model wrote, with your user's rights. It is version 0.1.0, for native
Windows 11 only, and verified on one machine. Read the [status and limits](./project/status/) before you rely on it.
</Aside>
